## 0. 核心任务与使用场景

### 0.1 这个应用只做两件事

1. **导图（主任务）**：把相机里的照片导到手机相册，越快越省事越好。
2. **选图（兼顾）**：只挑几张想要的导，不要求用户先把 1000+ 个文件看一遍。

这两条决定了后面所有条文。**任何规则如果让任务 A 变慢、或让任务 B 变难找，就是错的规则**，
即使它更容易被脚本断言。

### 0.2 任务 A：插上 → 全导新片 → 走人

目标路径（数字是**目标值**，不是现状；现状差距见 0.2.1）：

| 步 | 谁做 | 动作 | 用户心里想的事 |
|---|---|---|---|
| 1 | 用户 | 插数据线，相机侧选 MTP | 「插上就行」 |
| 2 | 系统 | USB 授权弹窗 → 点「允许」（**1 次点击**，系统层） | 「允许」 |
| 3 | 应用 | 自动开始扫描（插线触发 `USB_DEVICE_ATTACHED`） | 无 |
| 4 | 应用 | 扫描完成即进入照片墙首屏（顶栏徽标 + 日期分组 + 一个主 CTA，文案见 `T-CATALOG`） | 无 |
| 5 | 用户 | 点 1 次主 CTA（文案见 `T-CATALOG`） | 「导吧」 |
| 6 | 应用 | 传输页 → `T-DONE`（`Done` + 数量/容量 + 位置图标 + `Open`） | 无 |

**目标**：总点击 **2 次**（系统授权 1 + 应用内 1）、**0 次目录理解**、**0 次手动全选**。
按实测速率 21.43 MB/s 推算（`RESEARCH-android-usb-raw-a7c.md` §12.3；ILCE-7C fw2.00 / Android 15 / USB MTP）：
20 张 24 MP RAW ≈ 0.47 GB ≈ **23 秒**；1023 个文件 12.75 GB ≈ **10 分钟**（只计传输，含文件系统写入，不含枚举）。

- 「自动开始扫描」**已落地（#17）**：`Main.java` 的 `onNewIntent` 接前台插线、`receiver` 的
  `ACTION_USB_DEVICE_ATTACHED` 分支与 `autoScanOnLaunch`（冷启动检测）汇到同一个 `requestScan`，
  重复投递由 `AttachGate.java` 的 `public synchronized Admit admit` 去重（同一次插拔不得开两个会话）。
  残留依赖仍写在 §0.11 第 7 行：默认 USB 处理者要用户首次勾一次「一律打开」（系统弹窗，应用无法绕过），
  探针 `com.rea.mtpprobe` 占着默认处理者时插线拉不起本应用。**不得**再把「先点主按钮」写成流程的一部分。
- 「新片」指相机里**本机未导入过**的文件。**判定依据依赖一个尚不存在的前置件**：持久化的「已导入照片索引」
  （见 §0.11 第 1 行）。建议主键 `size + relPath`，与 `Journal.java` 类注释里「size + relPath 才是跨会话重识别的主键」那句一致；
  拍摄时间只能作可选辅助字段，且**未验证**。首次使用等于全部文件。

#### 0.2.1 现状与目标的差距（不是推断，取自本仓库实测）

| 环节 | 现状 | 目标 |
|---|---|---|
| 起步 | 插线与冷启动会自动扫描（#17：`autoScanOnLaunch` / `onNewIntent` / `handleAttach`）；状态区仍是单行摘要 `COPY_COLD`（`No camera · auto-detect on plug-in`），不是 `T-COLD` 的「图标 + `No camera` + `Connect camera`」。另受两件事限制：首次插线要用户勾一次「一律打开」；探针占用默认处理者时插线拉不起本应用 | 插线自动扫描并直接落到 `T-COLD` 形态的首屏（相机未连接时） |
| 首屏「新片」数量 | 依赖 §0.11 第 1 行的已导入索引，当前不存在 → 算不出「新」 | 徽标口径是照片数；「新片」语义待索引落地 |
| 选片 | 必须先把 1526 个对象当树看一遍，再全选 | 照片墙按日期分组，点格即选 |
| 主 CTA | `Import` 与全选/清空同权重并排 | 单一主 CTA（`Import all N` / `Import N`，见 `T-CATALOG`） |
| 结束 | 只有统计与 `getFilesDir()/imported`，相册不可见（F17） | `T-DONE` + 位置图标 + `Open` |

### 0.3 任务 B：挑几张再导（兼顾选图）

| 步 | 谁做 | 动作 |
|---|---|---|
| 1 | 用户 | 插线 + 授权（同任务 A） |
| 2 | 应用 | 扫描完成即进入**按日期分组的缩略图网格**（不展开目录树） |
| 3 | 用户 | 点 2 张（2 次点击）；底部 CTA 变为 `Import 2`（文案见 `T-CATALOG`），已选数只出现在 CTA 里 |
| 4 | 用户 | 点 1 次导入 |

**目标**：总点击 ≤4（系统授权 1 + 选 2 张 + 导入 1）；「在 800 张里找到 2 张」≤3 次操作（按日期跳到那天 + 过滤抽屉）、
≤30 秒（**计时起点＝扫描完成**；扫描本身约 59 秒，见 `Catalog.java` 头注释里「全量约 59 秒」那一段）、滚动不超过 3 屏（验收见 `T-03`）。

### 0.4 明确不做（写下来是为了挡住后续往功能清单上堆）

- **遥控拍摄**：PTP/IP 遥控是后续方向（见 AGENTS.md §1），本版本不做。
- **删相机文件 / 格式化 / 改相机设置 / 触发快门**：红线是探针只读（AGENTS.md §2 第 2 条），永不进入本应用。
- **应用内解码 ARW**：依赖缩略图或内嵌 JPEG，**未真机验证**（见 §0.7），本版本不承诺。
- **Wi-Fi 传输**：实测 Wi-Fi PTP 只有 0.95 MB/s（RESEARCH 第 11 节），不作为本版本路径。
- **云同步、账号、修图**：不做。

### 0.5 按人群写场景（首屏必须随人群不同）

| 人群 | 一次的量 | 首屏最该看到 | 主 CTA | 不该看到 |
|---|---|---|---|---|
| 「全存」型 | 拍 20 张全要 | **照片墙 + 一个 CTA**（顶栏徽标 + 日期分组 + `Import all 20`） | `Import all N`（见 `T-CATALOG`） | 目录树、文件夹已选、常驻过滤条件、说明句、统计卡 |
| 「挑图」型 | 拍 800 张只要 3 张 | 按日期分组的照片墙 + 日期组头 + 过滤图标 | 选中后 `Import 3`（见 `T-CATALOG`） | 1000+ 行文本、文件夹勾选、每格徽标、每格勾选圈 |

- **主 CTA 随选择切换**：文案只在 §4.5 `T-CATALOG` 定义一次，本条与全文其他位置一律引用，不复述。
- **首屏不靠说明句**：判断「该点哪里」由「唯一焦点 + 一个实心主按钮」承担（判定见 `T-05` / `T-06`）。

### 0.6 信息架构重排：人是按「什么时候拍的」找照片

一级 = **拍摄日期分组**（人记的是「我上周三拍的那组」，不是 `DCIM/100MSDCF`）；
载体 = **缩略图网格**；原始 MTP 路径**降级**为可展开的 `Location details`，不作主展示。

| 维度 | 现状（照抄 MTP 结构） | 重排后（照人的结构） |
|---|---|---|
| 一级分组 | 日期目录（`DCIM/100MSDCF`） | 拍摄日期分组（组头如 `Jun 7 · 12 · 284 MB`，数字是**组内聚合**） |
| 载体 | 文本行 | 缩略图网格；缩略图不可得时用降级块（§0.7） |
| 层级表达 | 4 个空格缩进（`Main.java` 的 `makeRow` 中 `label.append("    ")` 那一行） | 日期组头 + 组内网格，不用空格表层级 |
| 滚动 | 渲染上限 800 行、底部恒 ≤200 条提示（缺口实际 726，F6） | 组内滚动；全局计数按 `C-08` / `C-09` |
| 原始路径 | 主展示之一 | 只在 `Location details` 展开时出现 |
| 首屏主操作 | 无（必须先理解树） | 单一主 CTA（§4.5 `T-CATALOG`） |

- **分组依据**：优先 EXIF `DateTimeOriginal`（**未验证**，见 §0.7 第 3 行）；其次文件修改时间
  （**未验证**，见 §0.7 第 4 行）；两者都取不到时按 MTP 目录分组（目录名即日期），并在组头标注「按目录名」，
  **不得**把它说成拍摄时间。

### 0.9 验收方法论：可测量性服务于体验

1. **体验优先**：为了能被 `dump` 判定而牺牲易用性的条文必须改；不许要求 UI 增加冗余文本去迎合正则。
2. **机械可测的保留**：bounds 相交、对比度、文案正则、计数求和这类能客观判定的，继续作为硬断言。
3. **只能人眼判断的，就写人工判定**：给出场景、判定人、通过标准，不硬造测不准的代理指标。
   例：「一眼能否看出哪些是日期分组」——人工判定：2 名未参与开发者，5 秒内正确指认 ≥90%。
4. **任务流优先于条文**：任务流验收（§8.5 的 `T-01`～`T-06`）与任何旧条文冲突时，以任务流为准，
   并回改条文（见 §10 第 5 条）。

## 1. 信息架构与状态模型

### 1.1 单一状态源

- **必须**由唯一一个 `UiState` 枚举驱动界面（`COLD`、`PERMISSION_PENDING`、`SCANNING`、`CATALOG_READY`、
  `IMPORTING`、`PAUSED`、`DONE`、`ERROR`、`EMPTY_CATALOG`、`UNAVAILABLE`），不得让多个控件各自表达状态。
- **必须**在状态切换时清理上一状态的临时内容。**例外只有三种**：`SCANNING`、`DONE`、`ERROR` 允许保留上一轮结果，
  但必须标注 `Last import`（§0.10），不得与当前状态混排；其中 `SCANNING` 若保留照片墙，必须整体 `enabled=false` 并置灰。
- **不得**让两个进度同时活动；扫描环与传输环必须分属不同控件且互斥显示。
- **状态落点只有两类，职责各自唯一**（除下列落点外的控件**不得**再表达状态）：

  | 类别 | 落点 | 唯一职责 | 允许出现于 |
  |---|---|---|---|
  | 常驻指示 | 顶栏连接图标（相机图标，无文字） | 表达「相机是否已连接」 | 全页常驻 |
  | 常驻指示 | 底部主 CTA | 表达「现在能推进什么」（文案见 §4.5） | 按 §1.2「允许操作」；非本态动作不出现 |
  | 内容区唯一焦点 | 图标（相机 56 dp / 禁止）/ 细环 + 计数 / 传输环（180 dp）/ 照片墙 | **状态的主表达**；每个状态恰好一个，字面与形态见 §4.5 `T-xx` 的「唯一焦点」列 | 全状态；形态随状态切换 |

  内容区焦点是状态的**主表达**（L-04）：`COLD` / `EMPTY_CATALOG` / `UNAVAILABLE` 用居中图标，
  `SCANNING` 用细环 + `320/1526`，`IMPORTING` / `PAUSED` 用 180 dp 传输环，`CATALOG_READY` 用照片墙；
  扫描环与传输环分属不同状态、互斥显示（见本节上一段）。
  顶栏的设备短名（如 `a7C`）只作标识，不承担状态；日志/详情入口默认不可见（L-05）。

## 2. 布局层级与触达安全区

> 本节针对 #16 一类「控件被系统栏/顶栏覆盖」的结构性成因，不是修一次按钮位置。
> 定稿用 Web 的 `env(safe-area-inset)` 表达安全区；Android 侧**一律**用 Compose 的 `WindowInsets.systemBars`
> （或 `safeDrawing`）换算，**不得**把 `env(...)` 当作实现。

**术语定义（本节提供唯一定义，术语表 §0.10 只登记用词）：**

- **顶栏**：应用顶部承载相机图标、设备短名与徽标的横向容器。合法实现三选一：
  (a) 自绘顶栏，容器语义标签固定为 `topBar`，高度 56 dp（不含状态栏）；
  (b) 沿用平台 ActionBar（`android:id/action_bar`），此时它就是「顶栏」；
  (c) Compose `TopAppBar`（高度固定 56 dp）+ `WindowInsets.statusBars`，容器语义标签固定为 `topBar`。
  L-03/L-04/L-05、§2.1 的「顶栏高度」均指这一个容器。
- **顶栏自身控件**：`bounds` 完全落在顶栏 `bounds` 之内的可点击控件（设备名、徽标等）。
- **系统栏**：status bar 与 gesture bar（navigation bar），**不含**顶栏。中文叙述统一写「系统栏」；
  断言里可写节点名 `status_bar` / API 名 `navigationBars`，两者指同一对象。

- **L-01** 内容区让出系统栏。判定对象是 **inset/padding 之后实际承载内容区的容器**，不是根容器自身：
  该内容容器的 `bounds.top` **必须** ≥ 状态栏底边（保留 ActionBar 时还须 ≥ ActionBar 底边）。根容器允许从 `[0,0]` 起排，
  `setDecorFitsSystemWindows(false)` 的实现方式正是这样，**不得**把根容器 bounds 当作判红依据。实现二选一：
  (a) `WindowCompat.setDecorFitsSystemWindows(false)` + 对内容容器（或根容器的 padding 内边界）施加 `WindowInsets`；
  (b) 使用无 ActionBar 主题（`Theme.Material.NoActionBar` 或等价）并自绘顶栏，再按 insets 让位。
  **`library` 与 `photo` 两页**必须显式施加上下 inset：顶栏吃 `statusBars`，底部 CTA/内容吃 `navigationBars`；
  原型里 `library` / `photo` 的 `pt-safe`、`pb-safe` **类名存在，但本文件内没有对应的 `@supports` 定义**
  （三页中只有 `transfer` 定义了），因此实际未生效——这两页的写法**不得照抄**。
- **L-02** 可点击控件不得被系统栏与顶栏遮挡。任何 `clickable=true` 控件：
  (1) 与系统栏的矩形交集**必须**为空（交集高度 0）；
  (2) **不得**被顶栏遮挡——其 `bounds` 与顶栏 `bounds` 的交集**必须**为空；
  **唯一例外**是「顶栏自身控件」（其 `bounds` 完全落在顶栏内，本身就是顶栏的一部分）。
  验收用 `uiautomator dump` 的 `bounds` 做矩形相交判断；不允许「视觉上能看见一半」。
- **L-03** 首屏主操作可见。主 CTA **必须**在第一屏、不滚动即可见；**不得**因为抽屉/提示条高度变化把主按钮挤出屏幕或挤到顶栏下。
- **L-04** 纵向分区固定。顺序恒为：顶栏 → 内容区（唯一焦点，可滚动，占剩余高度）→ 底部操作区（固定）→ 手势条安全区。
  状态**不再**单占一条固定状态栏：状态由内容区的唯一焦点承担（环/照片墙/图标）。
  任何区块**不得**因内容变多而挤占其他区块的固定高度。
- **L-05** 日志不得占首屏。日志/明细**必须**收进可折叠抽屉，默认收起；入口是「长按顶栏设备名」或 `Details` 按钮，
  默认不可见。展开时覆盖内容区，**不得**把主操作向下推。
- **L-06** 底部操作区避让手势条。底部按钮/进度区**必须**叠加 `navigationBars` inset 的 padding；
  按钮高度 ≥48 dp；与手势条之间视觉间隔 ≥8 dp。
- **L-07** 横排按钮可换行。一行放 3 个及以上按钮时**必须**允许换行或收进溢出菜单；大字号下**不得**横向裁切。
  溢出菜单按钮属于「顶栏自身控件」，按 L-02 豁免，但其可点区域**必须** ≥48 dp × 48 dp（A-01）。
- **L-08** 整格/整行可点。网格单元**必须**整格可点（点格即切换已选），**不得**只有格内的小图标可点；
  日期组头**必须**整行可点（点行即折叠/展开）。
- **L-09** 不用覆盖式定位。**不得**用 `AbsoluteLayout`、负 margin、`translationY` 把可点控件压到系统栏/顶栏下方。

## 4. 文案规范

### 4.1 状态话术

- **C-01（改写）** 每个状态的主文案只有**一行**，**≤20 字符**（含字母、数字、单位与标点，不含空格），
  且**不得**含正文句或「下一步」说明句；状态文案见 §4.5。
  **唯一例外**是 `ERROR`：允许两行——一行 ≤20 字中文原因 + 一个动作图标；完整三段式进 `Details` 抽屉（C-11）。
  口径 = 字符数；`·` 只作分隔符，不计入字符。
- **C-02** **不得**只写无对象的英文状态词（`Waiting`、`Loading`、`Busy`）；中文兜底文案（仅 `ERROR` 卡片与失败提示）
  同样**不得**省略对象（「等待开始」「无设备」属禁用话术）。
- **C-03（改写）** 界面词一律用 §0.10「界面用词（英文）」列；中文**只**用于 `C-19` 允许的错误原因。
  本文件描述实现机制时会写「传输」，但它**不得**出现在用户可见文案里；用户侧一律用 `Import`。
- **C-04** 状态**不得**写进按钮文字或日志里：点击主 CTA 后按钮文案不变，状态由环/照片墙承担
  （原型把 `Ingesting…` 写进 `span` 的做法**不得**照抄）。
- **C-19** 界面主语言**必须**是「图标 + 简短英文词」：状态、按钮、列表标签、朗读文案一律用英文。
  中文**只允许**出现在 `ERROR` 卡片的三段式正文与失败提示里，每段 ≤20 字。
  1. **判定顺序**：先看图标能否独立表达（按 §0.9 原则 3 人工判定：5 秒内 ≥90% 未参与开发者能指出状态）；
     能，则只留图标 + ≤1 个英文词；不能，再补到 ≤3 个英文词；**不得**用中文句子补位。
     这两个数字**只**是**图标旁标签**（工具栏、按钮、列表标记这类单点标签）的词数预算；
     状态主文案仍按 `C-01`（≤20 字符、无正文句），本条的 `≤1` / `≤3` **不**适用。
     图标资源缺失时用英文词单独承担（文字兜底），**不得**因此退回中文句子。
  2. **不得**出现「为说明而说明」的解释句、技术自证（协议名、opcode、哈希、规范章节号）、统计卡片堆叠。
  3. 英文用句首大写（sentence case），**不得**全大写喊话；专有名词（`USB`、`ARW`、`GB`、`MB`）保持原写法。
  4. 同一个动作在按钮与正文里**必须**用同一个词（按钮 `Connect camera`，正文不得换成 `Retry`）。
- **（已废止）** 首屏说明句条（原 §4.1 第 7 条）：与 §0.8 同步删除，改由「唯一焦点 + 一个实心主按钮」承担。

### 4.2 数字口径（本组是数字、单位与小数位的唯一权威）

- **C-05** 容量**必须**按 1024 进制换算（1 GB = 1024 MB），单位写 `GB` / `MB`；

- **C-08（改写）** 总量在界面上**只**允许一个数字徽标（顶栏右侧），口径 = **照片数（ARW 张数）**，

## 5. 反馈与进度

- **P-01** 任何超过 1 秒的操作**必须**立即出现可见反馈（状态或进度）。
- **P-02** 超过 10 秒的操作**必须**可取消；扫描与导入**必须**都有取消入口。
- **P-03（改写）** 进度**必须**包含「已完成 / 总数」（环下 `12/36`）；速率与剩余时间**不得**进主视觉，
  只允许在 `Details` 抽屉里出现，且**不得**出现「正在估算」这类句子。
- **P-04** 同一时刻**只能有一个**活动进度；扫描与传输**不得**同时存在。
- **P-05（改写）** 非 `IMPORTING` / `PAUSED` 状态**不得**出现 `Pause` / `Resume` / `Cancel` 传输控件
  （不是置灰，而是不渲染）。
- **P-06** 结果**必须**按 `T-DONE` 自解释（唯一模板）；**不得**另起「成功 N」这类说法。
- **P-07** 取消或失败后**必须**保留已选与已传记录；再次开始时**必须**在 `Details` 抽屉显示 `Skipped N existing`，
  **不得**把断点续传伪装成「跳过 0」；主视觉不出现该句。
- **P-08（保留，标「规范待更新」）** 保存**位置**必须对用户可达：`T-DONE` 只留位置图标，
  路径写进 `Location details`。目标目录是公开媒体目录（`MediaStore` / `DCIM/Import`），
  与 **#28**「默认私有目录、入相册需授权」尚未统一，随 #28 定稿后回改本条；当前实现写 `getFilesDir()/imported`（F17）。
- **P-09** 点主 CTA 前**必须**做一次空间预检：目标剩余空间 < 计划大小 + 5% 缓冲时**必须**禁用 CTA 并给一行
  `Low space`（12 sp）；差额进 `Details` 抽屉，**不得**新增卡片或进度条。
- **P-10（改写）** 点主 CTA 前**不得**弹任何模态摘要；CTA 本身已写数量（`Import all N` / `Import N`），
  位置与容量进 `Details` 抽屉。所有路径（含已选 ≥100 个或 ≥1 GB）统一为「点一次即开始」。

## 6. 空态、错误态、不可恢复态

- **E-01（改写）** 空态**必须**是「一个图标 + 一个主动作」（`T-COLD` / `T-EMPTY`）；**不得**加解释句。
- **E-02** 错误**必须**就地显示，**不得**只写日志或只弹 Toast；错误态**必须**保留用户选择。
- **E-03** 不可恢复态（相机休眠/USB 挂起）**必须**给出「拔插数据线」的明确步骤，并提供 `Connect camera`；
  **不得**让应用在后台重试 8 次却不告诉用户（项目实测重试唤不醒相机）。
- **E-04** 功能未实现态**必须**用 `UNAVAILABLE` 状态表达，**不得**伪装成进行中、失败或完成（见 C-16）。
- **E-05** 扫描到空目录**必须**进入 `EMPTY_CATALOG`，**不得**停留在 `SCANNING` 或显示空网格。

## 7. 无障碍

- **A-01** 所有可点击目标**必须** ≥48 dp × 48 dp（当前列表行 32 dp，见 F9）。
  复选框类控件（仅降级形态可能出现）热区**不得**低于 44 dp（原型 20 dp 不达标，见 V-11）。
- **A-02** 正文对比度 ≥4.5:1，大字 ≥3:1（WCAG 2.1 AA，实算值见 V-07）。
- **A-03** 每个可交互控件**必须**有可读文本或 `contentDescription`；**不得**只有图标。
- **A-04（改写）** 传输环（`IMPORTING` / `PAUSED`）是**导入进度**的唯一载体，**必须**提供 `role=progressbar`
  等价语义 + 当前值 + 文本值（Android：`ProgressBarRangeInfo(current, 0..100)`，朗读 `12 of 36`；
  Web 对应 `aria-valuenow` / `aria-valuetext`）。`SCANNING` 的细环只呈现 `T-SCANNING` 的计数文案，
  不另加进度语义（两环分属不同状态、互斥显示，见 §1.1）。原型把环整体置为对读屏隐藏，**不得**照抄。
- **A-05（改写）** 网格朗读：单元读 `Photo, selected` / `Photo, not selected`；
  日期组头读 `Date group <date>, N photos, <size>`；`Folder` 只用于 `Location details` 里的真实 MTP 文件夹
  （本版 `Location details` 只展示原始路径、不含文件夹行，故该词本版不出现）。
  朗读模板**只有两态**，字面量按 §0.10 固定大小写。
- **A-06** **必须**支持系统字号 1.3× 与 2.0×，不裁切、不重叠，按钮可换行（U-24）。
- **A-07（暂不适用）** 深色模式随 `V-08` 暂不适用；「不得仅靠颜色表达已选/错误」由 V-11 与 A-02 承担。
- **A-08** 状态变化**必须**通过无障碍事件播报（扫描完成、导入完成、错误），**不得**只改静态文本。

## 10. 变更流程

1. 任何触及界面的 PR **必须**在正文「验收对照」引用本文件的 `U-xx` / `T-xx`，并贴出对应 dump/截图/录屏。
2. 发现规范未覆盖的状态，**必须**先在本文件补一条约束与验收项，再实现。
3. 本文件的修改与代码修改可以同 PR，但**必须**在 PR 正文单列「规范变更」小节说明新增/修改了哪几条。
4. 本文件由 `check_doc_links.py` 保证链接可达；新增路径**必须**同步更新 [AGENTS.md](../../AGENTS.md) §6 文档索引。
5. **任务流优先**：`T-01`～`T-06` 与任何条文冲突时，以任务流为准；改条文，不改任务流（除非任务流本身被证伪）。
6. 同一事实只许有一处定义：文案在 §4.5、数字口径在 §4.2、允许操作在 §1.2、状态覆盖在 §1.2 + §8.2、
   危险操作防护在 §3.4 / V-17、朗读文案在 §7、用词在 §0.10、界面语言（图标 + 英文词）在 §4.1 `C-19`、
   前置依赖在 §0.11。其他位置一律引用编号，**不得**复述。
7. §0.11 第 1 行「已导入照片索引」的独立单是 **#20**；实现前须先在该单下补真机/单测证据，
   不得在 UI PR 里顺手补一个「近似实现」。
8. **行号引用禁令**：本文件正文**不得**写物理行号（「文件名 + 冒号 + 数字」的写法，以及不带文件名的裸冒号数字）——
   行号是物理坐标，改一次就漂。引用代码一律写「文件名 + 该文件里可唯一 grep 的字符串」，引用本文件用编号（V-16 / C-08）或
   相对位置（§0.7 第 3 行），引用实测数据用章节号 + 数值（`RESEARCH-android-usb-raw-a7c.md` §12.3 配 21.43 MB/s）。
   自检：按上述字符组合在本文搜一遍应零命中（完整命令写在 PR 正文，**不写进本文件**，否则命令自身会命中自己）。
9. 引用被改动的代码时，锚点串**必须**能在目标文件里 `grep` 到且能唯一定位；串被改名时，改锚点而不是退回写行号。
10. **文案迁移收口（`#31` / `#34`）**：`#31` 落地的中文按钮与状态文案（`COPY_COLD`、全选、清空、开始导入、暂停、
    继续、`扫描中 %d/%d`、摘要长句）在本文件中**行为保留、文案作废**；`#34` 确立的「图标 + 短英文」语言由
    §4.1 `C-19` 承担。代码侧字符串随 PR-2 的 Compose 三屏一次性替换，不在文档 PR 里改动。
11. 本文件与定稿冲突时，**以定稿为准并回改本文件**；**不得**在代码里另立一套文案或 token 绕开本文。
