## 研究：安卓通过 USB 连接 Sony a7C 传 RAW

产出：`RESEARCH-android-usb-raw-a7c.md`（工作区根目录）

核心结论：
- 15 个仓库全部是 Wi-Fi JSON Camera Remote API / BLE / Windows 桌面，**无一实现 USB PTP**，均无法取 RAW。
- Wi-Fi AP 模式下 `getContentList` 只暴露 JPEG 原始文件，RAW 不可下载（协议层限制，非 App 问题）。
- Creators' App 不支持 a7C 一代（仅 7C II/7CR），a7C 无 PlayMemories，不能装相机内插件。
- 索尼 2024-04 免费公开 **Camera Remote Command**（PTP 命令参考，ILCE-7C 在列，USB 接口，无 OS 限制）——"锁"只在客户端缺失。
- a7C USB = USB 3.2 Gen1 5Gbps，卡槽 UHS-I；USB 模式有 Mass Storage / MTP / PC Remote / USB Streaming。

三条路线：
- A 零开发：相机切 Mass Storage + 手机挂载 U 盘拷 ARW（索尼 Transfer & Tagging 官方文档同路径）
- B Termux + libgphoto2 + termux-usb（免 root，需给 gphoto2 打 `--usb-fd` 补丁走 libusb_wrap_sys_device）
- C 自写安卓 App：Kotlin USB Host + PTP initiator，积木 = camlib / Android_USB_PTP_Lib / libgphoto2 的 camlibs/ptp2

关键约束：MSC 与拍摄互斥；PC Remote 与 Wi-Fi 遥控互斥；卡 ≥64GB 需 exFAT。

## 追加2：勘误 + 从本机 IED 入手（关键转折）

**勘误**：a7C 的 PC Remote 支持 Wi-Fi Direct / Wi-Fi Access Point，走 PTP/IP（TCP 15740），
有 RAW+J PC Save Img = RAW & JPEG → IED 在 Wi-Fi 下能过 RAW。
"Wi-Fi 只能传 JPG"只对手机端 Ctrl w/ Smartphone（旧 JSON Camera Remote API）成立。

IED 分层（C:/Program Files\Sony\Imaging Edge）：
- LjCore.dll = PTP 编解码核心（导出仅 LjCore/LjCommandData，符号已剥）
- LjAdapter/Lja_PTP_USB.dll（libusb+libusbK）、Lja_PTP_IP.dll（PTP/IP，带 libssh2）、Lja_PTP_WIA.dll
- 适配器接口 sony_lajiao::IDeviceConnection；导出 EnumCameraObjects/Connect/GetCameraObjectInfofromDetector
- Strings.xml = 设备属性词表；PC Save Image Size=2M 时 RAW 被丢弃（客户端逻辑）

架构结论：一套 PTP 核心 + 可插拔 transport → 安卓端应先做 PTP/IP（纯 TCP，免 USB 权限），
再换 USB transport。已修正报告路线顺序（新增 B′）。

## 追加3：Lja_PTP_IP.dll 静态分析

导出 11 个 C ABI 方法（extern "C"，插件 ABI）：
Init / Release / GetAdaptorName / GetConnectionTypeName / GetFingerprint / EnumCameraObjects /
ReleaseEnum / GetCameraObjectInfofromDetector / Connect / CancelConnection / ReleaseConnection
+ 5 个 LjCommandData 的 C++ 成员导出（跨 DLL 按值传递，故 IED 自带 msvcp140/vcruntime140）。
USB 版只有 9 个（无 GetFingerprint / GetCameraObjectInfofromDetector）。

调用方式：LjCore.dll 用 LoadLibraryExW + GetProcAddress 动态加载（静态导入表里没有 Lja_PTP_*，
DLL 名字面量搜不到 → 运行时拼）。
连接对象：RTTI 显示 sony_lajiao::IDeviceConnection ← DeviceConnectionPTP（虚表，符号已剥）。

**关键发现**：Wi-Fi PC Remote 不是裸 PTP/IP，而是
SSDP 发现 → 设备描述 XML（X_SSH_Support / X_PTP_PairingNecessity / X_PTP_MediaServerSupport）
→ libssh2 SSH 登录（password / keyboard-interactive）→ channel_direct_tcpip_ex 转发 → 隧道内跑 PTP/IP。
依赖：WS2_32 + IPHLPAPI.GetAdaptersInfo；libssh2 为动态加载（27 个符号，含私有变体 libssh2_channel_read_ex_for_cbm）。

影响：上一版"先做 PTP/IP 比 USB 便宜"要收回一半；USB PTP 仍是安卓端最干净路径。

产出：tools/pe/{pe_inspect.py, FINDINGS-Lja_PTP_IP.md}
待验证 4 项：SSH 端口/账号、描述 XML(SSDP LOCATION)、PTP/IP 握手、LoadLibraryExW 参数。

## 追加4：a7C 实测抓包结果（Wi-Fi AP 模式，IED）

抓包 captures/wlan.pcapng（148MB）。相机 192.168.3.17，PC 192.168.3.5，同一路由器。

关键结论：
- 走 PTP/IP over 裸 TCP 15740，**a7C 没有 SSH**（0 个 22 端口连接，描述 XML 里无 X_SSH_Support）→ 推翻之前从 Lja_PTP_IP.dll 推的 SSH 隧道结论（仅适用其他机型）
- 发现：UPnP/SSDP + HTTP 64321，GET /dd.xml、/DigitalImagingDesc.xml，X_PTP_PairingNecessity=Necessary，PTP 3.00
- 握手：Init_Command_Request(host name) → Ack(ILCE-7C) → OpenSession(1)
- 初始化：0x9201 SDIOConnect(1/2/3) ×3 → GetDeviceInfo → 0x9202 GetExtDeviceInfo(300) ×2 → 0x9209 SetDevicePropValueEx(3206B)
- 实时取景：GetObjectInfo + GetObject(0xFFFFC002) 轮询（1617 次）
- 取文件：GetObjectInfo(0xFFFFC001) → GetPartialObject(0x101B, handle, offset, ≤1MB) 循环；ARW≈23.6MB 压缩 RAW + JPG 0.6–0.9MB，DSC0000x
- 事件走第二条 TCP 连接（Init_Event_Request），索尼私有事件 0xC2xx
- 实测 ≈0.95 MB/s（含取景）

## 追加5：直连探针实测 —— 「下载卡里旧照片」走不通，改道 MTP

用户明确需求变更：不是"新拍的"，而是**卡里**已有的旧 RAW。

用 tools/sony-ptpip/probe.py 直连相机（192.168.3.17:15740）做只读验证：

- **GUID 是配对身份**：随机 UUID → Init_Fail type=5 reason=1，连试 6 次全拒；
  用 IED 的 `dd4b11b9-280d-43` → 立即 ACK。相机记住配对方 GUID。
- **事件通道必须先建**：正确顺序 Init_Command_Ack → 第二条 TCP Init_Event_Request(conn)
  → Init_Event_Ack → 才发 OpenSession。少了这步 OpenSession 一个字节都不回，只超时（不是被拒）。
- **dataPhase 位 IED 一律填 1**，含 OpenSession 这种无数据操作，照抄。
- 补上后 OpenSession → OK；索尼引导序列 SDIOConnect(1/2/3)+GetExtDeviceInfo(300)×2 全 OK。
- 但 **GetStorageIDs / GetNumObjects / GetObjectHandles / GetStorageInfo 全部 AccessDenied**，
  仅 GetObjectInfo(0xFFFFC001) 可通。GetDeviceInfo 明确列出支持 0x1004/0x1007
  → 是**会话类型权限**，不是实现缺失。**PC Remote 会话不开放存储枚举，此路到头。**
- 顺带修 bug：ObjectInfo 宽高原写 28/32，正确 26/30；文件名长度字节在 **52**、文件名从 53 开始
  （规范算应是 48，索尼多 4 字节填充；抓包 tid=299 ARW 与实时探针 0xFFFFC002 两处交叉验证）。
- 另一坑：相机空闲时 GetObjectInfo(0xFFFFC001) 返回 OK 但数据 0 字节，不是错误码，必须判长度。

**最终结论（已写入报告第 11 节 + 改写第 0 节）**：
- 要旧 RAW → 相机 `USB连接 = MTP`，安卓原生 `android.mtp.MtpDevice` / 任意 MTP 文件管理器，免 root。
- 要边拍边传 → PTP/IP，只能拿 0xFFFFC001 那张。
- 两者互斥（USB连接同一时刻只能一个模式），完整替代 App 应做双模。
- 速度：Wi-Fi PTP ≈0.95 MB/s；USB MTP 估 20–40 MB/s。

产出：probe.py 重写（事件通道 + GUID 配对 + sony_init + 枚举失败矩阵诊断）、
报告 0 节与 11 节、FINDINGS 第 5 节。

## 追加6：MTP 路线真机验证全部跑通（决定性结论）

环境：魅族 20 Infinity / Android 15 (API 35)，无线 ADB `192.168.3.206:41473`，OTG 直连 a7C。
产出新工程 `tools/android-mtp-probe/`（手搓 APK，不依赖 Gradle：aapt2+javac+d8+zipalign+apksigner）。

**核心结果：**
- USB 枚举：VID 0x054C / PID 0x0D2A / ILCE-7C，接口 6/1/1（Still Image），端点 0x81 IN / 0x02 OUT / 0x83 int
- MtpDevice.open() 成功，24 个操作；存储 0x00010001 "Storage Media" 59.4 GB
- **1526 个对象：503 文件夹 / 511 ARW(11.9GB) / 511 JPEG / 1 MP4**
- 说明 MTP 会话下 GetStorageIDs/GetObjectHandles 全部正常 → 与 PTP PC Remote 的 AccessDenied 形成对照，
  坐实「不是相机不给，是会话类型不给」
- 下载 3 张 24MP ARW：20.6–23.7 MB/s，批量 73.29MB/3.42s = **21.43 MB/s**（Wi-Fi PTP 0.95 MB/s，约 22 倍）
- 完整性三重校验通过：字节数一致、MD5 手机与 PC 完全一致、文件头 49 49 2A 00 合法 TIFF

**三个坑：**
1. 相机在 MTP 会话结束后约 1 分钟挂起 USB：open() 卡 10s、getStorageIds() 空，8 次重试(70s)无效，**必须拔插线**。
2. `getObjectHandles(sid, 0xB101, 0)` format 过滤不可信：0.17s 返回 754 个，但逐个 getObjectInfo 只有 511 个是 0xB101，
   数字对不上账（疑似重复句柄）。**用全量 getObjectHandles + 逐个 getObjectInfo**（39ms/个，1526 个约 59s）。
3. Flyme 自带文件管理器 `com.meizu.filemanager` 未声明 USB host → 这台机器没有现成 App 可用。

**加分发现**：manifest 挂匹配 Sony VID 的 `USB_DEVICE_ATTACHED` intent-filter 后，
插线系统自动授予权限并拉起 App（权限回调直接 granted=true，无弹窗）。

已写入报告第 12 节（含 12.6 最小骨架代码）与 `tools/android-mtp-probe/README.md`。
校验样本留在 `out/`（3 张 ARW + screen.png + mtp-report.txt）。
