# 归档区（docs/archive）

本目录只放**可读的过程记录**：某次探索做了什么、结论是什么、证据在哪里。
原始证据本身（logcat / dump / 截图 / pcapng / APK）不入库，规则见 `.gitignore` 的
「归档区只收文本记录」一段。

## 为什么只收文本记录

只放行 `.md` 与 `.txt` 两种文本记录，`png` / `log` / `bin` 等原始材料仍被忽略。

- 原始证据体积大：单次抓包上百 MB（实测值见 `INDEX.md`）、一张手机截图 0.7 MB、一张 RAW 24 MB；
- 原始证据含设备身份（序列号、配对 GUID、内网地址），不适合随仓库分发；
- 「结论 + 怎么重新生成证据」比证据文件本身更可复用。

需要原始证据时，按 `INDEX.md`「证据」列写的方法在本机重新生成。

## clone 之后本地没有证据文件，是预期行为

原始证据（抓包、手机侧报告、截图、RAW 样本）只在作者本机保留。任何人 clone 之后本地
没有这些文件，**不是仓库损坏**。早期这些文件曾被跟踪，历史提交里仍有 blob，可按路径
恢复到工作区（只动工作区、不改索引，恢复后仍被 `.gitignore` 忽略）：

```powershell
git restore --source=<历史提交> --worktree -- <证据文件路径1> <证据文件路径2>
```

恢复后建议按 blob 哈希与历史提交逐项比对（工作区 CRLF 与 blob LF 的字节差属正常）。
真实事故：`#94` 合并后，主工作区 `git pull --ff-only` 把 5 个已从索引移除的旧跟踪文件
按删除处理，本地副本随之消失——`git rm --cached` 只对执行它的 worktree 生效；后来就是
用上面的命令取回并逐项比对一致的。（这是**工作区恢复**那件事，与 `PR_GUIDE.md` 里
「merge 后 3 秒自动关单」是两件事，别混为同一则。）

## 目录约定

| 项 | 约定 |
|---|---|
| 文件名 | kebab-case，如 `2026-11-mtp-throughput.md`；纯文本记录用 `.txt` |
| 日期 | 目录或文件名前缀写 `YYYY-MM`，与 INDEX 的「日期」列一致 |
| 正文 | 写结论、环境、证据来源与复现命令；不复制大段日志 |
| 索引 | 每新增一篇，在 `INDEX.md` 追加一行 |

## INDEX 格式

`INDEX.md` 一行一条：`日期 | 主题 | 结论 | 环境 | 证据（本地文件名，不入库）`。

「证据」列写**本地文件名**，不写链接——这些文件不在仓库里，写成链接既会让
`check_doc_links.py` 报断链，也会让读者点进 404。

## 与其它目录的关系

- `docs/archive/2026-11-audit/`：2026-11 早期可行性核查与仓库审计的存档，已从 `docs/history/` 整棵迁入。
- `docs/research/`：长期有效的调研报告（已建立，见该目录 README）。
- 本目录：按时间归档的一次性过程记录；结论若长期有效，应上提到 `docs/research/` 或主报告。
